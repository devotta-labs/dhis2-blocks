## Install a block

Blocks are installed from the repository's shadcn-style source registry. The
installer copies the block source into your project's configured components
alias and records its dependencies — you own and can edit the result.

<InstallCommand item="working-list" />

Your project needs Tailwind CSS and a valid shadcn `components.json`
configuration. The registry manifest declares the npm dependencies each block
requires; install them alongside the block.

## Provide the DHIS2 runtime

Blocks read data through `@dhis2/app-runtime` and TanStack Query. The
simplest host is the same `@dhis2/app-adapter` the DHIS2 Application Platform
uses: it discovers the server and API versions, loads the current user and
locale, and renders the sign-in dialog when authentication is needed.

```tsx
import AppAdapter from '@dhis2/app-adapter'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'

const queryClient = new QueryClient()

export const App = () => (
    <AppAdapter appName="My app" appVersion="1.0.0" url="/dhis2">
        <QueryClientProvider client={queryClient}>
            {/* your app — blocks inside reach the live API */}
        </QueryClientProvider>
    </AppAdapter>
)
```

## Route the API through a same-origin prefix

Blocks expect API traffic on the same origin — this site uses `/dhis2`.
Session cookies, CORS, and mixed-content problems disappear because the
browser only ever talks to your own origin.

During development, Vite's proxy forwards the prefix to your backend:

```ts
// vite.config.ts
export default defineConfig({
    server: {
        proxy: {
            '/dhis2': {
                target: 'http://127.0.0.1:58080',
                changeOrigin: true,
                secure: false,
                rewrite: (path) => path.replace(/^\/dhis2/, ''),
            },
        },
    },
})
```

Forward the full DHIS2 path space — authentication endpoints, metadata,
tracker data, icons — and keep credentials out of the bundle: either users
sign in with their own account through the adapter's dialog, or the proxy
injects a demo account upstream (see `DOCS_DHIS2_USERNAME`/`DOCS_DHIS2_PASSWORD`
below).

A static `vite build` does not include the dev proxy. In production, serve
`dist/` behind any standard reverse proxy that maps `/dhis2` to your DHIS2
instance. This repository ships a minimal Node server for that role:

```bash
DOCS_DHIS2_URL=https://your-dhis2.example pnpm serve:docs
```

The `serve` script runs `server.mjs` with Node's `--env-file-if-exists`
flag, so the same `.env` conventions apply.

## Run the docs against a seeded backend

The repository seeds the Sierra Leone demo database plus the metadata its
examples reference:

```bash
pnpm docs:up        # DHIS2 2.42 (pinned) on http://127.0.0.1:58080
pnpm dev:docs       # http://localhost:3002
```

`pnpm docs:up:<version>` pins another supported backend (`41`, `43`, `dev`).
The docs stack uses its own Compose project, so `pnpm e2e:down` and friends
can never remove it. `pnpm docs:down` stops and removes containers while
keeping the database volume; `pnpm docs:reset` destroys the volume and
re-seeds from scratch.

To point the docs at an existing development instance instead:

```bash
DOCS_DHIS2_URL=https://play.im.dhis2.org/dev pnpm dev:docs
```

The `/dhis2` proxy authenticates every upstream request out of the box as
the published `admin`/`district` demo account — every DHIS2 demo and play
instance ships those credentials, so live previews always load data
directly with no sign-in dialog. `DOCS_DHIS2_USERNAME`/`DOCS_DHIS2_PASSWORD`
override the account (set them in `.env` — both Vite and `server.mjs` load
it automatically), and `DOCS_DHIS2_ANONYMOUS=1` disables injection to pass
requests anonymously and show the adapter's sign-in dialog instead. Only
point the injected account at demo or play instances; it grants every
visitor whatever the account can do.

## Add a page or example

Pages are MDX files under `apps/docs/src/pages/` — add the file, then list it
in `apps/docs/src/navigation.ts` so it appears in the sidebar.

Examples live in `apps/docs/src/examples/<block>/`: each is a self-contained
React component built on the public block API. Register it in
`apps/docs/src/examples/registry.ts` with `live: true` when it needs the
connected DHIS2 instance or `live: false` for a standalone render — the
preview and the Code tab are generated from the same file, so they cannot
drift apart.
