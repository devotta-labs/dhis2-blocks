These steps start from an app created with the DHIS2 `create-app` CLI. The
shadcn CLI copies a block's source into your app and installs the npm
packages it uses.

<Steps>

### Set up Tailwind CSS

Skip this step if your app already uses Tailwind CSS v4. Otherwise, install
Tailwind and its Vite plugin:

<AddPackagesCommand packages="tailwindcss @tailwindcss/vite" dev />

Add the plugin to `viteConfigExtensions.mts`:

```ts
// viteConfigExtensions.mts
import path from 'path'
import tailwindcss from '@tailwindcss/vite'
import { defineConfig, ConfigEnv } from 'vite'

const viteConfig = defineConfig(async (configEnv: ConfigEnv) => {
    const { mode } = configEnv
    return {
        clearScreen: mode !== 'development',
        resolve: { alias: { '@': path.resolve(__dirname, 'src') } },
        plugins: [tailwindcss()],
    }
})

export default viteConfig
```

Create `src/index.css` and import it at the top of `src/App.tsx` with
`import './index.css'`:

```css
/* src/index.css */
@import 'tailwindcss' important;
```

DHIS2 adds a global CSS reset to every app. The `important` flag lets
Tailwind's utility classes override it, so blocks look the way they are
designed.

### Initialize shadcn

Skip this step if your app already has a `components.json`.

The shadcn CLI recognizes a Vite project by its `vite.config` file. Rename
`viteConfigExtensions.mts` to `vite.config.mts` and point `d2.config.js` at
the new name:

```js
// d2.config.js
viteConfigExtensions: './vite.config.mts',
```

Then run:

<ShadcnCommand args="init" />

The CLI asks for a component library and a preset. Blocks don't depend on
either, so pick what suits the rest of your app.

### Add a block

<InstallCommand item="working-list" />

This installs the Working List. Each [block page](/blocks/working-list) shows
its own command.

### Use the block

Import the block from your components folder:

```tsx
import {
    WorkingList,
    WorkingListTable,
    WorkingListToolbar,
    WorkingListFilterControls,
    WorkingListViewSwitcher,
} from '@/components/working-list'

export const ChildProgrammeList = () => (
    <WorkingList programId="IpHINAT79UW" orgUnitId="y77LiPqLMoq">
        <WorkingListViewSwitcher />
        <WorkingListToolbar>
            <WorkingListFilterControls />
        </WorkingListToolbar>
        <WorkingListTable />
    </WorkingList>
)
```

Program `IpHINAT79UW` and organisation unit `y77LiPqLMoq` exist on the DHIS2
demo database; use IDs from your own instance otherwise. Each
[block page](/blocks/working-list) documents its full API.

</Steps>

## Updating a block

Run the same `add` command again. The CLI asks before it overwrites your
files, so commit your own changes first and review the diff afterwards.

## Contrast

Blocks follow the contrast the user asks their system for. With "Increase
contrast" on macOS or a contrast theme on Windows, text, borders, focus rings
and status colours switch to higher-contrast values. Your app needs no code for this:
the theme sets each colour as a `--dhis2-<role>` variable and changes it under
`@media (prefers-contrast: more)`.

Blocks also keep their edges, focus and states in Windows forced colours, where
the system replaces every colour: menus, popovers, dialogs, cards and tooltips
gain a border, and fields and options keep a visible outline.

For your own code next to the blocks, use the same roles, so it changes with
them:

- Text: `text-dhis2-foreground`, `text-dhis2-muted-foreground`,
  `text-dhis2-subtle-foreground`.
- Lines and surfaces: `border-dhis2-border`, `bg-dhis2-background`,
  `bg-dhis2-muted`.
- Statuses: `bg-dhis2-<tone>-subtle`, `bg-dhis2-<tone>-muted`,
  `text-dhis2-<tone>-strong` and `bg-dhis2-<tone>-indicator`, where the tone
  is `neutral`, `info`, `success`, `warning` or `destructive`.
- In a style or a chart config, the variable itself, such as
  `var(--dhis2-info-indicator)`.

Parts that blocks take from `@dhis2/ui`, such as the context selector's bar and
menus, the calendar date inputs, the org unit tree and the column transfer,
keep their own colours and do not change with the contrast setting.
